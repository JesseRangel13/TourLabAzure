## 4. Architectural & Behavioral Observations

* **Dual-Order Saga Compensation**:
  * In the original architecture, compensation assumed a fixed order of operations. The new Azure implementation handles both refund-then-release and release-then-refund permutations depending on exactly when the failure or cancellation occurred, ensuring stock is never leaked and refunds are never duplicated.
* **Uncertain Payments & ManualReview**:
  * When payment provider calls fail ambiguously (timeouts or transport drops after submission), the system captures the fault mode and executes 5 progressive reconciliation queries. If still ambiguous, it escalates to `ManualReview`. Administrators can inspect the simulated provider state, resolve the outcome, and trigger same-ID reconciliation to complete or compensate the Saga cleanly.
* **Audited Dead-Letter Queue (DLQ) Replay**:
  * DLQ messages are inspected via non-locking peeks with 5-minute renewable windows and 60-second owner leases.
  * Replay validation rejects malformed payloads, invalid correlation headers, or messages older than the 14-day retention limit.
  * When approved, replayed messages are dispatched to the original queue or topic with fresh transport IDs (preserving logical/business IDs) and logged to an audit table; the original DLQ message is completed only after the replacement is accepted by the broker.
* **W3C Distributed Trace Context**:
  * `LabTelemetry` ensures W3C `traceparent` headers are propagated from HTTP endpoints through Service Bus application properties and restored inside background workers (`IInboxConsumer`, `OutboxDispatcher`), enabling full end-to-end trace correlation in SQL without leaking sensitive payload data.
