## 4. Key Architectural & Operational Highlights

* **Pure Bicep Resource Group Model**:
  * Infrastructure is provisioned via native Bicep templates targeting a single resource group (`targetScope = 'resourceGroup'`).
  * Microservices share a single Linux App Service B2 plan (`apiSku = 'B2'`) with individual Web Apps for Gateway, Catalog, Reservations, Payments, and Notifications, alongside an isolated Flex Consumption Azure Functions resource for Receipts.
* **Strict Least-Privilege Entra ID RBAC**:
  * Role assignments are provisioned with exact resource scopes:
    * `Catalog`: Storage Blob Data Contributor on `tourlab-azure-tour-images`.
    * `Receipts.Functions`: Storage Blob Data Contributor on `tourlab-azure-booking-receipts`; Service Bus Data Receiver on `booking-receipts` subscription.
    * `Reservations`: Storage Blob Data Contributor on `tourlab-azure-dashboard-keys`; Cosmos DB Built-in Data Contributor on `tourlab-azure-dashboard/bookings`.
    * `Gateway`: Key Vault Crypto User on `tourlab-azure-gateway-protection`; Key Vault Secrets User on `tourlab-azure-human-signing`.
* **Deterministic Deployment & Migrations**:
  * Application binaries and SQL scripts are compiled once, cryptographically hashed, and verified prior to deployment (`Build-Release.ps1` / `Test-Release.ps1`).
  * Database schema migrations are decoupled from application startup: runtime processes have zero DDL permissions (`CREATE TABLE`, `ALTER TABLE` denied). Migrations are executed by a dedicated, short-lived migrator principal.
* **Lifecycle Governance & Retention Safeguards**:
  * `Stop-AzureLab.ps1` stops application compute without destroying persistent data or configurations.
  * `Remove-AzureLab.ps1` defaults to deleting compute only. Deleting persistent storage or databases requires the explicit `-IncludeData` switch along with an inventory hash verification to prevent accidental data loss.
* **Transparent Cost Modeling**:
  * Retail prices API integration ensures that cost estimates are grounded in published rates rather than guesswork. Clear distinctions are made between active session hours and continuous retention costs.
