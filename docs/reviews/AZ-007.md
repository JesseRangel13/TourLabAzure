* **CQRS Boundary & Fail-Closed Outage Behavior (AC-A26)**: **PASS**
  * When Cosmos DB is disconnected or unavailable, dashboard query endpoints return HTTP 503 with safe ProblemDetails. SQL is deliberately *not* used as a fallback for dashboard queries, preserving architectural separation.

## 4. Architectural & Behavioral Observations

* **Explicit CQRS Boundaries**:
  * Authoritative mutations (booking creation, hold release, payment charge, refund, cancellation) execute strictly against SQL Server with ACID guarantees.
  * The dashboard reads exclusively from Cosmos DB. If Cosmos is unreachable, the API returns HTTP 503 instead of falling back to SQL Server queries, preventing database overload and maintaining strict architectural contracts.
* **Protected Keyset Continuation**:
  * Unlike offset-based pagination which suffers performance degradation on large datasets, pagination queries use `departureUtc DESC, id ASC` with `TOP(size + 1)`.
  * Continuation cursors are encrypted and HMAC-signed with ASP.NET Core Data Protection, embedding the owner ID, query filter parameters, page size, and timestamp expiration to eliminate cursor tampering.
* **Monotonic Event Processing**:
  * Because message delivery across Service Bus is at-least-once and can arrive out of order, the Cosmos projection document maintains an explicit `businessVersion`. Events with an older or equal version are silently acknowledged without mutating newer projection states.
