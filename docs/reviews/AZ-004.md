## 4. Architectural & Behavioral Observations

* **Explicit PeekLock & At-Least-Once Delivery**:
  * The `InboxWorker` deliberately disables SDK auto-complete (`AutoCompleteMessages = false`) and uses `ReceiveMode.PeekLock`.
  * Broker settlement strictly follows database commit. If a worker crashes between SQL commit and `CompleteMessageAsync`, the broker redelivers the message; the subsequent delivery hits the `Inbox` table, finds the existing message ID, and completes the broker message immediately without re-executing domain effects.
* **Correlation Filters vs Match-All**:
  * Topic subscriptions use specific SQL filters on user-defined properties (`ApplicationProperties["type"] = envelope.Type`). Inactive subscriptions configure a `1 = 0` false filter, eliminating cross-consumer noise.
* **Deterministic Pricing & Idempotency**:
  * Quotes are verified outside the transaction; quotes exceeding 5 minutes are rejected.
  * Same idempotency key with identical payload returns the stored HTTP 202 response. Modifying payload parameters under the same key correctly triggers HTTP 409 Conflict.
* **Durable Simulated Effects**:
  * Payments and notifications persist their state directly to dedicated service schemas (`payments.Charges`, `notifications.Receipts`). Fault injection modes (`CapturedFaultMode`) are durable and survive application restarts.
