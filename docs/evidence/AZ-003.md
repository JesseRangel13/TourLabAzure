## Scope and decisions

- Catalog-owned SQL tables/migration: Tours, Sessions, Quotes, Holds; existing owned Inbox/Outbox retained.
  Restricted runtime credentials still cannot use other schemas, DDL or migration history.
  UTC datetime2 conversion, checked integer MXN, explicit binary collation and business version checks.
- Explicit concrete CatalogQueries, CatalogCommands, QuoteHandler, InventoryHandlers; no generic repository,
  reflection dispatch, cross-service EF entities or direct database access.
- Source behavior ported selectively after inventory: CatalogOperations, InventoryHandlers, domain fields,
  DTO/integration messages and 13 inventory tests. No source credentials/data/migrations/build outputs copied.
  HTTP DTOs live inside Catalog. Shared.Contracts contains only integration contracts/envelope.
- SQL Server transaction application locks (finite timeout, Catalog-role namespace), UPDLOCK/HOLDLOCK,
  conditional available>=participants UPDATE, filtered nullable QuoteId uniqueness and constraint arithmetic.
  Outer owner transaction rollback includes Hold, stock and Outbox. No automatic transaction retry.
- Five-minute idempotent quote snapshots, accepted price/currency, participants 1..6, ten-minute hold;
  active future session; confirmation does not deduct again; expiry/release restores once; release tombstones retained.
  No purge shortens the required 14-day dedup/tombstone boundary.
- HoldExpiryWorker uses bounded 50-row scans, async scope per batch and per hold; two actual hosted
  instances and concurrent handler invocations are tested. No broker delivery is claimed.
- Durable Catalog event intents address one tourlab-azure-domain-events topic, with one Outbox delivery
  per logical event. The SQS versus Azure topic difference is resolved explicitly in D29.
  AZ-004 adds real broker routing/filtering/dispatch and Inbox consumption.
- Repeatable bootstrap creates two fresh Azure-only sample tours/sessions without resetting existing
  data, departure, capacity, versions or event intents. No imported database rows/resource IDs.
- Secured tour list/detail/Admin edits/sessions/price/capacity; generated authenticated Development-only
  OpenAPI; missing required JSON fields return safe 400. CSRF/origin, independent backend role/JWT and
  separate quote signer boundaries remain active.
- Angular typed transport; meaningful CatalogState actions/selectors; returned observable completion/errors,
  stale/cancelled-load guards, immediate per-user resets, serialized mutations without automatic retries;
  local typed reactive forms, search/pagination/detail and Admin controls.
- CRUD preserves source create/read/edit/activation; no invented hard delete of referenced history.
  Images, booking submission, fault selection, payment/broker success remain assigned later tasks.

See ../decisions.md D23-D29, ../catalog-execution.md and ../catalog-learning.md.
