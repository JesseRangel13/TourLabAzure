## Delivery and isolation

Notifications atomically accepts confirmed snapshot + unique ReceiptJob + GenerateBookingReceipt
Outbox with Inbox and normal simulated notification work. The actual .NET10 isolated Service Bus
Function claims an owned SQL lease/version, conditionally creates and verifies a private immutable
UTF8 Blob, commits Ready, then manually Completes. Safe duplicate, transient recovery, expired/lost
ownership and conflicting bytes are handled without overwriting the document or querying another
service schema. Owner/Admin status and bounded attachment are independently authorized by Notifications
and forwarded through the cookie BFF. Angular/NGXS adds status/loading/retry/download and account reset;
current authoritative booking state remains visibly separate from the historical confirmation.

## Deliberate compatibility and observed corrections

Earlier version1 ReservationConfirmed lacked accepted detail/time. The optional additive snapshot
retains original notification assertions, writes one legacy-snapshot audit, and never invents a
historical document. All new confirmed producer events carry the exact immutable snapshot/version.
The actual Saga test verifies the event against committed Reservations data; Notifications itself
cannot query that schema. Existing valid tour names remain accepted and print JSON-quoted text so
control characters cannot forge receipt lines.

Initial project editing duplicated a PackageReference (NU1504); the final csproj contains one pinned
reference and locked restore/build pass. Initial EF --no-build omitted Release and looked for missing
Debug output; rerunning with --configuration Release generated the correct migration. An unused
Angular import warning was removed; final build has no warning. A one-off shell-native SqlClient
diagnostic hit TdsParser initialization; no SQL result was claimed from it, and actual .NET test
processes supplied the verified SQL evidence.

The first full receipt run passed workflows but an explicit log check found no worker trace message.
ClearProviders had removed the Functions logging provider. Retaining it, allowing the worker category,
and emitting trace/span as structured fields fixed that gap. The final -SkipRelational run repeats
all3actual crash/host stages and4HTTPS tests and explicitly asserts the live trace in the host output.
